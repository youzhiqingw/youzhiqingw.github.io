# 真机跑通之前，先用 mock：Cursor 的四种模式与 MVP 节奏

页面和设计系统就位后，下一步是把它真正跑起来，并接上 AI 请求。这一阶段的关键不是"功能多全"，而是"流程先通"：先在真机上把页面交互跑顺，再逐步换成真实数据。

## 一、连真机，别只在模拟器里看

在 Xcode 里通过 USB 或网络连接自己的 iPhone，按 AI 的指引完成开发者模式等基础配置，就能把 App 装到真机上测试。vibe coding 里会遇到不少生僻词和报错，不需要全部搞懂，跟着步骤做、耐心解决即可。很多问题（网络请求、字体、布局）在模拟器里看不出来，真机一上就暴露。

## 二、API 先用 mock，把流程跑通

涉及大模型调用的 App，不要一开始就纠结接哪家模型、怎么调优。更聪明的做法是：**先用占位数据（mock）把页面流程和交互跑通**，模型选型和真实接口后面再换。这样可以先验证"用户能不能顺畅地走完整个流程"，而不是卡在接口调试上。

模型本身可以先用有免费额度的服务跑起来，等流程稳定后再按效果和成本切换。

## 三、按任务选 Cursor 模式，别全程用 agent

Cursor 这类工具有多种工作模式，用错了既费 token 又容易出错：

- **Ask（问答）**：提问、让它总结时用；
- **Debug（调试）**：排查具体报错时用；
- **Plan（规划）**：复杂任务先让它拆分步骤时用；
- **Agent（执行）**：真正让它写代码时再用。

默认往往是 agent，如果每一步都用 agent，token 消耗会很高。记住：**写代码才切到 agent，其余环节按需选更轻的模式**。

## 四、工具搭配：不只用 Cursor

Cursor 之外，善用其他 AI 工具能明显提效：**Claude** 在本阶段被大量使用——它的输出比另一款模型更稳，而且画流程图、架构图非常精细，一张架构图就能当页面原型用。此外，把"打字"换成**语音输入工具**（能把语音转成文字，并自动整理语句、润色翻译）也很解放双手，描述需求时尤其顺手。

## 五、用测试用例驱动代码质量

一个显著提升质量的做法是：**先写一份清晰完整的测试用例，再让 Cursor 写实现**。把正常情况、边界情况、异常情况都列出来，它写出的代码会更全面，后续你验收时也有据可依——尤其在多状态、多分支的核心流程上，这一步能省掉大量来回。

## 六、MVP 心态：别在第一版就抠细节

如果按"最小可行产品（MVP）"原则推进，进度会快很多。实际开发中很容易把大量时间花在抠视觉细节上。先让核心流程成立、真机可走通，细节留到流程稳定后再打磨。

## 小结

这一阶段的目标只有一个：**在真机上跑通完整流程**。方法是——连真机、接口先用 mock、按任务选对 Cursor 模式、用测试用例兜底质量、用 MVP 心态控制范围。流程通了，再谈模型效果和细节优化。
