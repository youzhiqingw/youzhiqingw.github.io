# Codex 从安装到上手：配置模型、办公实战与 AGENTS.md、Skill

Codex 是 OpenAI 推出的 AI 编程与办公助手（Agent，智能体）。它和直接在网页里跟大模型对话的区别在于：它能在你电脑上读文件、改文件、跑脚本，把一个完整任务从开头做到结尾。本文把这套工具的上手过程串成一条线：安装与模型配置 → 界面与必要设置 → 提示词怎么写 → 一个写周报的实战 → 用 AGENTS.md 和 Skill 把习惯与流程固化下来。

## 一、安装

### Windows

1. 先确认系统版本：按 `Win + R`，输入 `winver` 回车，查看 Windows 版本。Codex 对 Windows 有最低版本要求（早期要求约 1809/17763 以上，具体以官方当前要求为准），Windows 11 一般无需担心。
2. 打开 OpenAI 官方下载页，下载 Windows 安装包；双击后会跳转 Microsoft Store 完成安装。

### macOS

直接在官方页面下载 macOS 版，正常安装即可；后续配置与使用步骤和 Windows 一致。

## 二、接入模型：第三方 API 平台与 CC Switch

Codex 是 ChatGPT 旗下产品，默认只对接 OpenAI 的模型。国内直接使用有两种途径：一是通过网络访问订阅 ChatGPT 账号；二是接入第三方 API 中转站（一个转发模型请求、按用量计费的平台）。本文只讲第二种，不推荐任何具体平台。

这里需要先装一个配置工具 **CC Switch**：它用来管理和切换 Codex 所用的模型供应商。下载对应系统的最新版本安装即可。

### 配置三要素

在 CC Switch 中新建一个"自定义"配置，需要填三项，都能在你所用第三方平台的文档里找到：

- **供应商名称**：自己起一个标签，随意填写。
- **API 请求地址（base URL）**：Codex 发起模型请求时实际访问的地址，必须填第三方平台给的地址，请求才会走到它的服务。
- **API Key**：一串鉴权字符串，相当于通行证，第三方平台靠它识别是你在调用、从而从你的账户扣费。

**默认模型名**不用背：到第三方平台的"模型广场"，点开你想用的模型，页面上 `model` 字段的值就是要填的模型名。其余选项保持默认。

保存后在 CC Switch 中启用该配置，按提示重启 Codex，左下角模型名发生变化即生效。随便问一句（如"今天天气如何"），能正常返回就说明接通了。

### 一个常见坑：登录界面卡住

如果按上面配完仍停在登录界面、无法进入，问题通常出在模型提供方。在 CC Switch 配置里要把 **model provider 显式改为 `custom`**——否则 Codex 仍默认走 OpenAI 官方提供方，即便填了 base URL 也不会生效。改好后保存，回到 Codex 选择"使用其他方式登录"，粘贴第三方平台的 API Key 继续即可进入。

> 模型版本、CC Switch 界面与配置项会随版本更新变化，操作以工具当前文档为准。

## 三、界面与几个必要设置

### 项目与线程

打开 Codex 后先建一个项目：可以新建空白项目，或"使用现有文件夹"指向本地某个目录（例如在 D 盘建一个 `codex-test`）。项目本质上就是本地的一个文件夹，Codex 会把对话归档在它名下。

在一个项目下可以新建多个对话窗口，每个窗口叫一个**线程（thread）**。各线程拥有独立上下文——你在这个窗口聊的内容不会串到另一个窗口。因此最佳实践是：在同一个项目下，把不同问题、不同步骤放到不同线程里做。

### 三栏界面

- **左栏**：功能入口，新建任务、拉取请求、插件、项目与任务列表。
- **中栏**：对话区，显示你和模型的往来。
- **右栏**：输出区，模型写出的代码、文档会列在这里，点开可预览文件内容；后续还能打开浏览器、执行操作。

### 建议调整的设置

- **语言**：若自动检测没认出中文，手动设为简体中文。
- **显示上下文窗口使用情况**：打开后能看到还剩多少上下文。即便 Codex 有自动压缩，也建议在完成一个任务后手动压缩上下文，节省额度。
- **权限**：默认的"完全访问"会让模型自动执行所有操作。如果担心误删文件，可关掉完全访问，让危险操作弹窗等你确认；工作风险低时再打开全自动。
- **语气/风格**：按个人偏好选择，例如偏务实的风格。

### 几个高频操作

- **切换模型与推理强度**：在高级设置里切换模型档位；"推理强度"越高，模型思考越深、耗时越长、越耗额度。流程性任务用中等即可，需要深度规划时再调更高。
- **加号菜单**：可把本地文件/文件夹加入上下文；"目标"模式让它朝着一个目标连续工作直到完成；"计划模式"让它先就方案中需要你拍板的点和你确认，再动手。

## 四、提示词公式：指令 + 上下文

学 AI 不必先背完"提示词工程"再动手，先聊起来、在真实任务里迭代更有效。写好提示词记住一个公式：

> **提示词 = 指令 + 上下文**

- **指令**：你想让它做什么，直截了当，不要客套。
- **上下文**：完成这件事它需要知道的背景——为什么做、有哪些前置依赖。你和它的历史往来都会作为上下文一起传给模型。

普通人只要守住三点：清晰说明要做什么；复杂任务拆成几步；发现它理解跑偏就及时打断、补充纠正。做得多了，原本要十句话才能说清的事，后来五句话就够。

## 五、实战：让 Codex 写一份周报

用一个小项目把上面的概念跑通：把一周零散的工作记录整理成一份 Word 周报，外加一份 Excel 行动清单。

### 准备：把素材放进工作区

工作区就是项目对应的那个本地文件夹。Codex 作为 Agent，对文件具备**增、删、改、查**的能力。把本周工作记录存成 Markdown（`.md`，一种纯文本格式，`#` 是标题、`-` 是列表，人和 AI 都易读），放进项目文件夹，再让它处理，它就能读到。

### 让它做，再迭代纠正

把任务用日常语言描述给它即可，不必背固定话术。首轮结果往往不完美——比如周报太啰嗦、Excel 多了用不到的列、甚至它自行"脑补"出一条并不存在的事项。这时不要重写，而是补充上下文去纠正：

- 告诉它读者是谁（例如"给没参与日常工作的同事看"），因此要简洁；
- 明确 Word 该有哪几节、Excel 该有哪几列；
- 指出它哪里自作主张（"多出的第 9 条从哪来的？"），要求不要擅自改动原始事实。

把这些背景补充进去，让它重做一轮。如果想让它先理清流程，可加一句："先不要创建文件，先检查并告诉我需要补充哪些信息，把任务拆出来再生成。" 它若发现信息不全，会主动向你提问。

> 生成过程中它可能写一个 Python 脚本来产出 Word 和 Excel，因此本机需要 Python 环境（3.12 或更新版本均可）。没装的话，可以直接让 Codex 带你装。

满意之后，可以让它把这次的经验总结成不超过五步的标准流程（读原始记录 → 明确读者与用途 → 提取分类 → 分别填入 Word/Excel → 校验），这正是下一步做 Skill 的基础。

## 六、AGENTS.md：项目里的长期约定

**AGENTS.md** 是放在项目里、给 Codex 读的一个 Markdown 文件。它和提示词的区别在于：提示词只影响当前这一轮对话，换个对话就没了；而只要你还在这个项目里工作，每次开新会话，Codex 都会自动把 AGENTS.md 的内容加载为上下文，相当于你不用每次重复叮嘱。

它有两个作用范围：

- **项目级**：放在项目根目录下的 `AGENTS.md`，只对当前项目生效。
- **用户级**：放在用户目录下 `~/.codex/AGENTS.md`，对你所有项目生效。

**建议优先用项目级**：用户级的内容多了容易互相干扰；确定某条规则确实想跨项目复用，再把它升级到用户级。

写 AGENTS.md 的思路，不是罗列"遇到 A 就做 B、遇到 C 不能做 D"这种琐碎规则（现在的模型已经能做好），而是把**做事的思维方式**写进去，让它像你一样判断：例如先识别任务处于哪个阶段、把真正需要你拍板的问题抛出来；区分"已验证的事实 / 合理推断 / 待确认的假设"；事实不足时明确标注假设而不是编造；出现分歧才暂停问你，其余按已确认的方向连续执行。

在项目根目录新建一个文本文件、改名为 `AGENTS.md`，把约定写进去保存即可；也可以直接让 Codex 帮你起草。

## 七、Skill：把可重复的流程固化下来

**Skill** 本质上是"按 Agent 要求的目录格式组装的一份工作流说明书"。它和 AGENTS.md 都是给 Codex 看的 Markdown，区别在于：AGENTS.md 是长期生效的约定，Skill 则是**遇到特定场景、被调用时才按流程执行**的一套办事步骤。

### 目录结构

一个 Skill 就是一个文件夹，核心是其中的 `SKILL.md`：

```
.agents/
  skills/
    <技能名>/
      SKILL.md        # 必须：名称、触发描述、执行流程
      scripts/        # 可选：被流程引用的脚本
      references/     # 可选：参考文档
      assets/         # 可选：模板、素材
```

同样分项目级（项目根目录 `.agents/skills/` 下）和用户级（用户目录对应位置），原则和 AGENTS.md 一样：优先项目级。

`SKILL.md` 里最关键的是顶部的 **name** 和 **description**：

- `name` 是技能名；
- `description` 决定**什么时候会被自动调用**——要写清"在什么场景下、要做什么"。写得太模糊（如"帮助处理办公事务"）就不会被准确触发；但对"辅助做方案决策"这类希望它逢事就想起来的 Skill，反而不必写太死。

### 两种做法

1. **流程已经很明确**：直接描述清楚要做的事（例如"交付文件检查助手"：读取交付要求 → 找出必备文件 → 逐个检查是否齐全、命名是否正确、是否为空 → 生成报告且不改原文件），让 Codex 按它内置的"创建 Skill"能力生成。
2. **流程还不明确**：先别急着写 Skill，先和 AI 把这件事完整做一遍、边做边纠正，等结果满意了，再让它把这套步骤总结成可复用流程，最后固化成 Skill。

调用方式很灵活：输入 `/技能名`、`$技能名`，或者直接用自然语言说"用某某技能帮我……"，Codex 会根据上下文自己判断是否调用。写好后同样要持续迭代——Skill 很少一次成型，用出问题就告诉它哪里不对、怎么改。

## 八、什么时候用哪个

- **只是这一次要做**：直接在对话里发提示词，不用固化。
- **希望只要还在这个项目里就一直遵守**：写进项目根目录的 `AGENTS.md`。
- **这是一套以后还会重复用的流程**：把它做成 Skill，需要时一句话调用。

## 九、小结

上手 Codex 的主线是：装好桌面版 → 用 CC Switch 接上第三方模型（记得把 provider 设为 custom）→ 在项目里用线程组织对话 → 用"指令+上下文"的方式下任务并迭代 → 把长期约定写进 AGENTS.md、把可重复流程沉淀成 Skill。模型版本、CC Switch 与界面细节会随版本变化，实操时以官方与工具当前文档为准。
